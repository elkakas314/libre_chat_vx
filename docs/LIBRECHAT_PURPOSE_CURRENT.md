# LibreChat VX — Purpose CURRENT

Date: 2026-10-07
Status: SOURCE_CURRENT

## Product role

LibreChat VX / NOSTROMO is not intended to become another programming or execution system.

Its primary role is:

1. conversation with the user;
2. intent interpretation and referential understanding;
3. unified observation of MANOJOS3, VX13, ORACULO and connected information sources;
4. visual explanation of complex state;
5. research and synthesis when material execution is not required;
6. preparation of precise target objectives when an external system must act;
7. reception and triage of notifications/events from those systems.

The target systems keep their specialist roles:
- MANOJOS3: governed construction/execution and receipts;
- VX13: its own domain modules/authority;
- ORACULO: advisory/specialist reasoning;
- LibreChat: interpretation, presentation, conversation and coordination.

## Removed specialization

The dedicated `CODIGO` inference profile is removed.

LibreChat may understand a coding-related user request, but it should translate that request to the appropriate specialist target rather than carrying a coding-specialist LLM identity of its own.

The existing BuildPanel remains only as a viewer for external work/build evidence. It is not a code editor or coding agent.

## One visible identity

The user interacts with NOSTROMO.

Provider, model and semantic profile are internal routing details. The default UI should not require the user to select provider/model personalities.

## Tentáculo

The visual Tentáculo HUD remains a presentation surface.

A lightweight cognitive companion is attached conceptually to it:
- interpret intent;
- read system state;
- research public information;
- navigate resources;
- compose visualizations/Artifacts;
- triage incoming events.

It has authority=false and cannot execute material work, mint authorization/receipts, scan arbitrary networks or read secrets.

## Research

LibreChat should handle ordinary internet research directly using native Web Search and scraping/read paths.

MANOJOS3 is not required for:
- public web search;
- reading public pages;
- organizing findings;
- building a comparison/timeline/diagram/artifact.

MANOJOS3 becomes relevant when the user asks for material execution on a governed target.

## Visual output

Prefer the representation that fits the information:
- hierarchy -> Resource Tree;
- chronology -> timeline;
- relationships -> Mermaid;
- alternatives -> comparison table;
- status -> StatusRail/summary;
- evidence -> Evidence view;
- exploratory UI -> interactive Artifact.

No new bespoke module should be added when a native LibreChat Artifact or existing cockpit surface is sufficient.
